# Phone PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An installable Android PWA for flow-breaker with Today, Habits, Inbox, quick-add, and alarm notifications with Done/Snooze buttons.

**Architecture:** `cmd/flow-breaker-web` is a Go server on the Intel Mac (Docker, `tailscale serve`). It serves embedded vanilla JS, proxies an allowlist of `/api/*` calls to the Pi daemon, subscribes to the Pi's ntfy stream, and turns each alarm into a Web Push. The service worker shows the notification and posts Done/Snooze back.

**Tech Stack:** Go 1.25 stdlib + `github.com/SherClockHolmes/webpush-go` v1.4.0; vanilla JS; Docker (distroless).

**Spec:** `docs/superpowers/specs/2026-10-30-phone-pwa-design.md`

## Global Constraints

- Android Chrome only. No iOS work.
- The browser talks only to this server; the server calls the Pi. No CORS.
- Guard (copied from `~/Personal/desk/guard.go`): host allowlist → 421; `Tailscale-User-Login` allowlist on every path except `/api/health` → 403; unsafe methods need `application/json` and a same-origin `Origin` → 403; strict CSP.
- Env: `WEB_ADDR` (`:8091`), `WEB_ALLOWED_HOSTS`, `WEB_ALLOWED_USERS`, `FLOW_BREAKER_URL`, `NTFY_URL`, `NTFY_TOPIC`, `NTFY_TOKEN`, `VAPID_SUBJECT`, `WEB_DATA` (`/data`).
- VAPID keys and the one subscription live in `WEB_DATA`, mode 0600.
- Today groups come from the daemon's `/status` (Overdue, Upcoming → Next + Later, Done). Habits come from `/habits`. No grouping or habit logic in JS.
- Repeat alarms buzz only when the ntfy priority rose for that task (`renotify`); otherwise they replace silently.
- No change to the Pi daemon, the ntfy server, or desk.

## Review Focus

1. A proxied path outside the allowlist (`/api/settings`, `/api/../task`) → 404, never forwarded. → Task 1 test.
2. A request without `Tailscale-User-Login` → 403 on every path but `/api/health`. → Task 1 test.
3. A subscription endpoint on a non-push host → 400, not stored (SSRF guard). → Task 2 test.
4. Push service answers 410 → subscription deleted. → Task 2 test.
5. ntfy message without a Done action → no push. → Task 3 test.

### Task 4: Frontend, service worker, manifest

**Files:** Create `cmd/flow-breaker-web/web/{index.html,app.js,style.css,sw.js,manifest.webmanifest,icon-192.png,icon-512.png}`.

Behavior:
- One page: header (date, "stale since" banner when a fetch fails), Today (Overdue / Next / Later / Done collapsed), Habits (streak + 4-week grid), Inbox; quick-add bar fixed at the bottom; a bell button to turn on notifications.
- Poll `/api/status`, `/api/habits`, `/api/inbox` every 30 s while visible and on `visibilitychange`.
- Tap a Today row → action sheet: Done, Snooze, Edit time (prompt → `POST /api/task/{id}` `{"time"}`). Tap an inbox item → prompt "when?" → schedule; long-press → delete confirm.
- `#add` in the URL focuses quick-add (manifest shortcut `/#add`).
- All writes send `{"source":"phone"}` with `Content-Type: application/json`.
- `sw.js`: cache the shell, never `/api/*`; `push` → `showNotification(title, {body, tag, data:{taskId, priority}, actions:[done, snooze], renotify})` where `renotify` = priority > the open notification's `data.priority`; `notificationclick` → action → `fetch('/api/task/{id}/{action}', POST JSON)`, body tap → open `/`.
