# flow-breaker v2 — design notes

Moving from "local TUI that yells at my Mac" to "Pi-hosted daemon that captures from anywhere and pushes alerts to anywhere."

---

## The problem being solved

v1 is 100% interrupt, 0% capture. Six alert types, habit grids, tmux flashes — all output. The only way *in* is a TUI running on the laptop, and `add` demands `HH:MM` as the first field.

Two consequences:

1. **Thoughts without a time can't be captured.** "Call the plumber" has no `HH:MM` attached at the moment it occurs. Requiring one means the thought stays in your head.
2. **Alerts only reach the desk.** Which is exactly where you're already too absorbed to notice them.

v2 fixes both by separating **capture** from **scheduling**, and **deciding** from **notifying**.

---

## Architecture

```
  phone / mac                        RPi (tailnet)                     phone / mac
 ┌─────────────┐                 ┌──────────────────┐               ┌─────────────┐
 │  dictation  │  POST /capture  │  flow-breakerd   │  ntfy publish │  ntfy app   │
 │  shortcut   │ ──────────────► │                  │ ────────────► │  (push)     │
 └─────────────┘                 │  - parser        │               └─────────────┘
                                 │  - scheduler     │
 ┌─────────────┐   TCP client    │  - tasks.json    │  ntfy publish ┌─────────────┐
 │  TUI        │ ◄─────────────► │  (sole writer)   │ ────────────► │ ntfy sub    │
 │  (viewer)   │                 │  - ntfy server   │               │ --exec →    │
 └─────────────┘                 └──────────────────┘               │ say/osascript│
                                                                    └─────────────┘
```

**Key invariant: the Pi is the sole writer of `tasks.json`.**

This kills the whole class of last-writer-wins bugs. Earlier drafts of this design used an append-only spool file (`spool.jsonl`) so a capture daemon and the TUI wouldn't clobber each other — **that's obsolete now.** One writer, no spool, no drain-on-tick. Delete it from the plan.

The TUI becomes a pure client. Swap the Unix socket for TCP bound to the `tailscale0` interface (or `tailscale serve` in front) so it's reachable from the Mac but never exposed to the LAN.

## Part 1 — Capture

### Endpoint

```
POST https://<machine>.<tailnet>.ts.net/capture
{"text": "wash the dishes in 16 min"}
```

Expose with `tailscale serve --bg 7777`. Real TLS cert, no self-signed warnings, no cert wrangling in any client. Do this instead of exposing the raw port.

**Always echo back the parse** in the response body — `"14:12 — wash the dishes"`. Clients display it as a toast. Silent misparses are worse than outright failures.

### Parser: heuristics first, LLM on miss

| Input pattern | Result |
|---|---|
| `in 16 min` / `in 2h` / `peste 20 de minute` | now + delta, `once` |
| `at 14:30` / `la 3` | today, or tomorrow if already past |
| `tomorrow 9` / `mâine 9` | date + `once` |
| `every weekday at 8` / `în fiecare zi` | `weekdays` / `daily` |
| **no time expression at all** | **inbox** |

Strip the matched span; the remainder is the description. Romanian aliases cost nothing to add and you'll use them.

If nothing matches and the text isn't obviously timeless, one Haiku call returning strict JSON `{time, recurrence, desc}` covers the long tail. Keep it as a fallback, not the default path — heuristics are instant and free.

### Clients (no speech code needed — both OSes hand you text)

**Android — HTTP Shortcuts** (open source, F-Droid or Play)
- POST to endpoint, body `{"text": "$$$input}"` with `input` as a text-input variable
- When the dialog pops, hit the mic key on the keyboard — that's Gboard dictation
- Home screen icon of its own
- Enable "show response as toast" → free echo-back
- Hands-free later via Tasker + AutoVoice, but *don't start there*; tap-and-speak is one gesture and never mishears a wake word

**Mac — Shortcuts.app**
- Dictate Text → Get Contents of URL (POST, JSON) → Show Result
- Assign a global hotkey in the Shortcuts sidebar
- The hotkey matters: no window to find, which is the whole point when you're deep in something

### Fail loudly

Pi unreachable, phone off the tailnet, daemon crashed — the request dies, and dictation-based capture is exactly where you won't notice. Toast errors in red, and give the shortcut a dumb fallback that always works (append to a note, SMS yourself).

A capture tool that silently eats 3% of your thoughts is worse than no capture tool, because you'll trust it.

## Part 2 — Inbox + triage

### Data model

- New top-level `inbox: []` in `tasks.json`. **A separate array, not `time: ""`** — this keeps every existing sort and alarm path untouched.
- Daily reset must skip it. Inbox items are immortal until explicitly killed.

### Triage task

One recurring task at a fixed time with a generated description: `"Triage inbox (7)"`.

**If the count is 0 it auto-completes and never fires.** This matters. A nag that fires on an empty queue trains you to dismiss it, and then it's dead for the days it mattered.

### TUI mode `i`

| Key | Action |
|---|---|
| `enter` | Promote — jump into existing add flow, desc prefilled, cursor on time |
| `d` | Delete |
| `t` | Tag |

Promotion should cost one keystroke plus four digits. Anything slower and triage becomes the new avoidance.

### Cap it

Past ~20 items, the triage alarm should say so loudly. An inbox you never empty is just a slower way of forgetting.

## Part 3 — Alerts out

The Pi has no mouth. `osascript`, `say`, `afplay` are macOS-only; tmux flash only helps if you're already looking at the terminal. So the model inverts: **Pi decides when, and pushes out.**

Add this as a seventh alert type behind the existing interface. `alert.go` barely changes shape.

### ntfy on the Pi

Self-hosted, bound to `tailscale0`, `tailscale serve` in front. Topic per purpose: `flow` for alarms, `flow-triage` later so you can mute one without the other.

### Android — ntfy app

- **Priority 5** for real alarms: bypasses DND, vibrates, repeats sound. Use **priority 3** for the 10-minute heads-up so the two feel different without you having to read anything.
- **Action buttons — build these carefully.** Attach `http` actions: Done → `POST /task/{id}/done`, Snooze → `POST /task/{id}/snooze`. Since the Pi is the sole writer, *tapping the notification is the state change*. No "I'll mark it later," which is where tasks go to die.
- Exempt ntfy from battery optimization; enable instant delivery. Self-hosted ntfy holds its own connection rather than routing through FCM — if Android kills it, alerts just stop arriving with no error anywhere.

### Mac — `ntfy subscribe --exec`

Pipe each message into a shell script that calls the existing `osascript` / `say` / `afplay` code. **All six v1 alert types survive unmodified** — they're just triggered by a subscription instead of a local ticker. The TUI becomes a viewer; the Mac keeps its mouth.

### Escalation

One ping won't reach you mid-flow. ntfy has no replace-by-id, so republishing stacks notifications — lean into it:

- Republish every 60s while unacked
- Step priority up at 3 min and 6 min
- Cap at ~10 min, then auto-snooze rather than burning the battery

Ten stacked notifications and a phone that won't stop is precisely the intervention being asked for.

### The silent failure

Phone drops off the tailnet (Tailscale toggled off, captive wifi) → nothing arrives, no error anywhere.

Have the Pi track unacked alarms. If one goes 15 minutes with zero interaction, fall back to something that doesn't depend on the tailnet — Telegram push, or SMS via a cheap gateway. One escape hatch outside the system being debugged.

## Part 4 — Claude Code integration

### Read path

Keep the CLI contract identical, swap only the transport. `flow-breaker nudge` prints the same one-liners; it just does `GET https://<pi>/nudge` instead of reading a local socket. The existing `claude-install` hook, the `Bash(flow-breaker nudge*)` permission, and the CLAUDE.md text all keep working untouched.

**The fallback must not lie.** v1's chain was socket → `status.json` → compute from task file. On the Pi there's no local task file, so if the tailnet is down the honest output is:

```
⚠️ flow-breaker unreachable — tasks unknown
```

Never `✅ All clear`. A false all-clear in the agent's context is worse than no hook, because you'll believe it.

### Use `UserPromptSubmit`, not just `SessionStart`

SessionStart fires once and then you're four hours into a session with stale context. `UserPromptSubmit` fires every turn — gate it so it emits *nothing* unless there's an alarm, something overdue, or something inside 10 minutes. Silent 95% of the time, loud exactly when it matters. Over the tailnet it's a couple of milliseconds.

```bash
# exit 0 with empty stdout = nothing injected
curl -sf --max-time 2 https://<pi>/nudge?quiet=1 || echo "⚠️ flow-breaker unreachable"
```

Let the Pi own the gating via `?quiet=1` rather than grepping emoji in bash.

### Write path — yes, but asymmetrically

Claude Code can absolutely mutate state; it's the same HTTP API the phone uses. But the permissions should not be uniform, because the two directions have opposite risk profiles.

| Command | Permission | Why |
|---|---|---|
| `flow-breaker capture "..."` | **auto-allow** | Purely additive. Worst case is a junk inbox item. |
| `flow-breaker add <HH:MM> "..."` | **auto-allow** | Same — a wrong task is visible and deletable. |
| `flow-breaker done <id>` | **ask** | Destructive and self-defeating. See below. |
| `flow-breaker snooze <id>` | **ask** | Same. |
| `flow-breaker clear` | **deny outright** | Never. There is no scenario where this is right. |

**The failure mode to design against:** an alarm fires mid-session, the nudge lands in context, and the agent — being tidy and helpful — marks it done or snoozes it so the "problem" goes away. You've now built an elaborate alerting system whose alerts are silenced by a robot on your behalf. Deny by default; let the phone notification be the only thing that can dismiss an alarm.

Add a `source` field to every mutation (`tui` / `phone` / `claude-code` / `api`) and show it in the history view. When something gets marked done and you don't remember doing it, you'll want to know who did.

Prefer IDs over substring matching for anything an agent calls. v1's `done <HH:MM or substring>` is fine for a human who can see the list; from an agent it's a fuzzy match that can silently hit the wrong task.

### Capture *from* Claude Code is the real win

Give it `Bash(flow-breaker capture*)` plus a line in CLAUDE.md: when you say "remind me to fix that TODO later," it goes straight to the Pi inbox instead of evaporating. Mid-session is exactly when you generate tasks you'll never otherwise write down.

### CLAUDE.md wording

Tell it to **surface** the nudge and continue — not to act on it. Otherwise an overdue task turns into the agent abandoning your refactor to discuss your calendar.

### Be clear-eyed about the limit

Every hook fires on *your* activity. The failure being fixed is the 90 minutes where you submit nothing because you're deep in a file. Claude Code cannot interrupt that — nothing running inside your editor can. **The phone push is the real alarm.** The hooks are a cheap way to keep the agent from cheerfully helping you blow past a 14:00 meeting.

## Pi-specific gotchas

**SD card burnout.** `status.json` written every 500ms is ~170k writes/day. That's a dead card in months. Put it on tmpfs (`/run/flow-breaker/`) and only persist `tasks.json` on change.

**Timezone.** Set `Europe/Bucharest` explicitly. Headless Pis default to UTC, and you'll lose an hour wondering why the 09:00 standup fires at noon.

**Build.** Cross-compile from the Mac: `GOOS=linux GOARCH=arm64 go build`. systemd unit with `Restart=always`.

## Unrelated but fixes a daily annoyance

The iCal manual download/upload cycle is unnecessary. Google Calendar → settings for that calendar → **"Secret address in iCal format."** Plain HTTPS URL, stays live, updates itself. `flow-breaker cal-add "<url>"`.

Treat it like a password — anyone holding it can read the calendar.

## Build order

1. **Move to Pi.** Daemon + systemd + tmpfs + timezone. TUI still local, talking over TCP.
2. **ntfy out.** Alerts reaching the phone is the single biggest behavioral win — v1's alarms can only reach you where you're already too absorbed to notice.
3. **Capture endpoint + two shortcuts.** Parse to a real scheduled task; skip the inbox for now.
4. **Point the Claude Code hook at the Pi.** Read path plus `capture` only — hold off on the write permissions until the rest is stable.
5. **Use it for a week.** Everything gets a time, even a guessed one.
6. **Then build the inbox.** Only after you've felt the "I have no idea when I'll do this" friction for real — you'll design it better from that side.

## One note to self

v1 was an elaborate planner built instead of using one. The fix here is a handful of small features, not a v2 rewrite.

The build is fun; the triage isn't. That asymmetry is the exact thing this system is meant to work around — so be suspicious of any step in this document that turns into a three-week project.
